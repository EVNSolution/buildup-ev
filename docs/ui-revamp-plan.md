# buildup-ev UI 개편 계획

> 결정: **범위 = 전체(영업·관리·특장)** / **주 기기 = 데스크톱(태블릿은 예정, 갤럭시탭 먼저)** / **폰트 = Pretendard 자체 호스팅**
> 전제: 2026-08-12부터 실서비스 운영 중 → **한 단계 = 그 자체로 배포 가능**
> 관련: `docs/design-system.md` (토큰·규칙), `frontend/public/icon-*.svg` (아이콘 완료)

---

## 0. 확정 사항과 미확인 사항

**확정**
- 스타일링: 라이브러리 도입 없음. **인라인 style + CSS 변수 유지** (혼재가 최악이므로 전면교체도 안 함)
- 폰트: Pretendard 자체 호스팅
- 개편 범위: 영업 → 관리 → 특장 순차
- 브랜드 색: 라임 `#C8D200` + 무채색

**미확인 (진행 중 확인 필요)**
- **데스크톱 OS 구성** — Windows 사용자 비율. 있으면 맑은고딕 폴백 구간에서 글자 폭 검증 필요
  (Pretendard 고정 후에는 영향 없지만, 로딩 실패 시 폴백 확인용)
- 태블릿 실제 모델·해상도 (도입 시점에 확정)

## 1. 설계 원칙 (브리프 반영)

### 1-1. 스크롤 주체 ★
페이지 전체 스크롤은 없다. 화면마다 **스크롤을 갖는 영역을 하나만** 정한다.

| 화면 | 스크롤 주체 | 고정 |
|---|---|---|
| 컨피규레이터 | 우측 옵션 패널 | 헤더 · 3D · 하단 가격바 |
| 견적·주문 목록 | 리스트 영역 | 헤더 · 필터바 |
| 마이페이지 | 리스트 영역 | 헤더 · 기간 필터 |
| 관리 — 견적/옵션DB | 표 본문 (헤더 행 고정) | 헤더 · 탭 · 검색바 |
| 관리 — 칸반 | 각 컬럼 내부 | 헤더 · 탭 · 컬럼 제목 |
| 특장사 칸반 | 각 컬럼 내부 | 헤더 · 컬럼 제목 |
| 모달(고객정보 등) | **모달 본문** | 모달 헤더 · 하단 버튼 |

### 1-2. 3D 영역 16:9
- 컨테이너 쿼리로 계산하는 현재 방식 **유지**. `aspect-ratio` 단독 사용 금지.
- 3D 자리에 무엇이 들어가도(로딩·에러·플레이스홀더) 16:9를 지킨다.
- 좌측 컬럼 폭은 3D 높이에서 역산 → 나머지가 거기에 맞춘다.

### 1-3. 적응 분기 (폭 기준 아님) ★
```
세로형 판정:  (height / width) > 1        → 가격 블록 가로 → 세로 배치
터치 판정:    @media (pointer: coarse)    → 여백 축소, 히트영역 확대
```
- 시안·검증은 **① 넓은 데스크톱 ② 태블릿 가로 ③ 세로로 긴 화면** 세 가지로 한다.
- 폭 기준 브레이크포인트는 보조로만 쓰고, 기기 판정에 쓰지 않는다.

### 1-4. hover 금지 규칙
- **정보·기능을 hover에 숨기지 않는다.** hover는 시각 피드백(테두리 톤 변화) 정도만.
- 트림 사양처럼 접히는 정보는 **명시적 토글 버튼**으로 연다.
- 툴팁이 유일한 설명 수단이 되면 안 된다 — 옆에 상시 캡션을 둔다.

### 1-5. 터치 타깃
| 상황 | 최소 크기 |
|---|---|
| 마우스(fine) | 28×28 (표 내부 버튼 허용) |
| 터치(coarse) | **44×44** — 표 내부 버튼도 예외 없음 |
- 터치에서 표 행 버튼은 크기를 키우거나 **행 우측 고정 영역**으로 분리한다.

### 1-6. 되돌릴 수 없는 동작
삭제 · 전자서명 발송 · 메일 발송 · 주문 확정.
- 다른 버튼과 **위치를 분리**(같은 줄에 나란히 두지 않음)
- 터치에서는 **확인 단계 필수**
- Danger 스타일(빨강 테두리)로 시각 구분
- 실행 후 되돌릴 수 없음을 확인 문구에 명시

### 1-7. 고객 노출 구분 ★ (신규)
상담 화면은 **고객이 함께 본다.** 화면 요소를 두 종류로 나눈다.

| 구분 | 내용 | 규칙 |
|---|---|---|
| **고객 노출 가능** | 3D, 옵션 선택, 해당 건 가격·보조금, 사양표 | 크게·명확하게 |
| **내부 전용** | 다른 고객 견적 목록, 영업 실적, 계정 관리, 원가 | **상담 화면에 동시 표시 금지** |

- 컨피규레이터 화면에는 **다른 고객의 이름·연락처·금액이 어떤 형태로도 나타나지 않는다.**
- 헤더의 사용자명·역할 전환은 유지하되, 목록·실적은 별도 화면에서만.
- 향후 "상담 모드"(내부 정보 숨김 토글) 도입 검토 — 6단계에서.

### 1-8. 저대비 배색 금지
- 야외·매장 조명 고려. **라임 위 흰 글씨 금지**(대비 부족).
- 라임은 배경으로 쓸 때 그 위 텍스트를 `#1A1A1A`로. 라임 텍스트는 흰 배경에서만.
- 본문 대비 4.5:1 이상 유지.

### 1-9. 긴 값 내성
시안·구현은 아래 값에서 깨지지 않아야 한다.
```
고객명 20자 · 주소 40자 · 상호 30자 · 금액 9자리(억 단위)
```
- 금액·날짜: `white-space: nowrap` + `tabular-nums`
- 이름·주소: 1줄 말줄임 (부모 `min-width: 0` 필수)
- 표: 헤더·본문이 같은 `grid-template-columns` 공유, 숫자열 고정폭
- **검증용 더미 데이터**에 위 최대 길이를 반드시 포함한다.

### 1-10. 비동기 상태
PDF 생성(견적서·계약서)은 서버에서 수 초 + 실패 가능.
- **진행 표시**: 버튼 자체를 로딩 상태로 (버튼 비활성 + 스피너 + "생성 중")
- **실패**: 인라인 에러 + **재시도 버튼**. 토스트만 띄우고 사라지면 안 됨
- **중복 요청 차단**: 진행 중 재클릭 무시

## 2. 권한 매핑

권한 없으면 **비활성이 아니라 숨김**. 요소별 소속 권한:

| 화면 | 요소 | 권한 |
|---|---|---|
| 컨피규레이터 | 견적 저장 | `quote.create` |
| 컨피규레이터 | 옵션 단가 표시 | (전원) |
| 견적·주문 | 목록 조회 | `quote.create` 또는 `stats.own` |
| 견적 상세 | 견적 확정 | `quote.confirm` |
| 견적 상세 | 수정 | `quote.edit` |
| 견적 상세 | 삭제 | `quote.delete` |
| 견적 상세 | 메일 발송 | `doc.send.email` |
| 견적 상세 | 전자서명 발송 | `doc.send.sign` |
| 견적 상세 | 서류 보기·다운로드 | `doc.view` |
| 주문 | 주문 전환·확정 | `order.confirm` |
| 주문 | 주문 조회 | `order.view` |
| 주문 | 단계 이동(칸반 드래그) | `order.control` |
| 마이페이지 | 내 실적 | `stats.own` |
| 관리 | 영업 성과(전체) | `stats.all` |
| 관리 | 옵션DB·무게상수·지역보조금 | `basedata.manage` |
| 관리 | 계정 관리·기능모듈 | `account.manage` |

**구현 규칙**
- 탭 자체가 권한에 묶인 경우, 권한 없으면 **탭을 렌더하지 않는다**(빈 탭 금지)
- 권한 없는 사용자가 URL 직접 접근 시 접근 불가 화면으로
- 탭이 전부 숨겨지는 경우의 화면(예: 관리 권한 0개)도 정의할 것

## 3. 단계별 계획 (각 단계 = 배포 가능)

### 0단계 · 폰트 고정 ★ 최우선
**왜 먼저**: 폰트가 바뀌면 모든 글자 폭이 달라진다. 이걸 나중에 하면 앞 단계 시안을 전부 다시 잡아야 한다.

- Pretendard **자체 호스팅** (CDN 의존 금지 — 현장 네트워크·차단 리스크)
- `woff2` subset(한글+라틴+숫자), `font-display: swap`
- weight는 **400 / 500 / 600 세 개만** 로드 (용량 절감)
- 폴백: `Pretendard, -apple-system, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`
- 전역 `word-break: keep-all`, 숫자 `tabular-nums`

**검증**: 전 화면에서 표 헤더 2줄 접힘·버튼 라벨 줄바꿈 없는지. Windows(맑은고딕 폴백)에서도 확인.
**배포 단위**: 이것만 단독 배포 가능. 시각 변화가 크므로 별도 배포 권장.

### 1단계 · 디자인 토큰 + 공통 컴포넌트
화면 로직은 건드리지 않고 **공통 요소만** 교체.

- `globals.css`에 토큰 정의 (색·타이포·간격·반경·그림자·모션)
- 공통: 헤더(EV& 로고 + `Buildup-EV` 워드마크), 세그먼티드 탭, 버튼 4종, 입력, 뱃지, 빈 상태
- 눌림 모션: `scale(.97)` + 비대칭 트랜지션(누를 때 90ms / 뗄 때 260ms 스프링)
- 동심원 반경 규칙 적용
- 파비콘·매니페스트 연결(이미 생성됨)

**검증**: 모든 화면에서 헤더·버튼이 동일하게 보이는지. 기능 회귀 없는지.

### 2단계 · 영업 컨피규레이터
가장 중요(고객이 보는 화면).

- 3D 16:9 유지 · 스크롤 주체 = 우측 패널
- 옵션 카드 선택 상태(라임 2px + 옅은 배경), hover 의존 제거
- 트림 사양은 **토글 버튼**으로 펼침
- 하단 가격바: 수식 흐름 유지, 금액 `nowrap` + `tabular-nums`
- **고객 노출 원칙 적용** — 이 화면에 다른 고객 정보 없음 확인
- 견적 저장 = `quote.create` 권한

**검증**: 3D 비율 / 긴 값(고객명 20자) / 저대비 없음 / 세 가지 화면비

### 3단계 · 영업 견적·주문 목록 + 마이페이지
- 리스트 아이템 규격 적용(좌 제목·부제 / 중 상태 / 우 금액·날짜)
- 빈 상태 3줄 구조
- 상세 진입 시 권한별 버튼 표시/숨김
- 되돌릴 수 없는 동작 위치 분리 + 확인 단계
- PDF 생성 로딩·실패·재시도

**검증**: 긴 값 리스트 / 권한 조합별 버튼 노출 / PDF 실패 시 재시도 동작

### 4단계 · 관리자
- 7개 탭 → 성격별 그룹핑 검토(운영: 견적·성과·칸반 / 기준정보: 옵션DB·무게상수·계정·기능모듈)
- 표: 헤더·본문 그리드 공유, 헤더 행 고정, 숫자열 고정폭 우측정렬
- 옵션DB: 변경 이력·되돌리기 = Danger 스타일 + 확인 단계
- 칸반: 컬럼 내부 스크롤, 드래그는 `order.control` 권한

**검증**: 표 정렬 어긋남 0 / 좁은 폭에서 가로 스크롤(컬럼 숨김 금지)

### 5단계 · 특장사 칸반
- 관리자 칸반과 컴포넌트 공유
- 작업 단계 이동 권한 확인

### 6단계 · 태블릿 대응 (도입 시점에)
구조는 0~5단계에서 이미 심어둠. 여기서는 **적용·검증**.

- `pointer: coarse` 분기 활성화 → 히트영역 44px, 여백 축소
- **`#root { zoom: 0.88 }` 제거하고 토큰으로 크기를 직접 제어** ★ (1단계에서 넘긴 빚)
  손가락 기기 전체를 zoom 으로 줄이고 있어, 컨트롤 높이를 손으로 되돌려 맞추는 중이다.
  현재 `--h-control: 50px` 은 **zoom 되돌림 값**(50 × 0.88 ≒ 44)이라, zoom 을 없애면
  **44px 로 환원**해야 한다. zoom 은 화면 전체를 뭉뚱그려 줄여 글자·여백·히트영역이
  같이 작아지므로, 줄일 것과 그대로 둘 것을 토큰에서 따로 정하는 편이 맞다.
- 세로형 판정 → 가격 블록 세로 배치
- **화면 회전 시 상태 유지** (입력값·선택 옵션 보존)
- **소프트 키보드**: 고객정보 모달 = 모달 내부 스크롤 + 포커스 필드 자동 노출
- 되돌릴 수 없는 동작 확인 단계 필수 적용
- 갤럭시탭(Chrome) 우선 검증 → iPad(Safari) 추가
- **"상담 모드"** 검토: 내부 정보 숨김 토글

### 7단계 · 휴대폰 (선택, 별도 판단)
- **조회 전용**으로 한정 — 견적 상태·서명 진행 확인
- 옵션 선택·견적 작성은 태블릿 이상에서만
- 전 기능 이식은 비용 대비 효과가 낮으므로 별도 과제로 분리

## 4. 하지 않는 것

- **3D 내부**: VIVAR iframe 시각화 전용. 건드리지 않음
- **견적서·계약서 PDF 레이아웃**: 화면과 별개 템플릿. UI 개편이 서류를 바꾸지 않음
  (서류 변경은 별도 과제)
- **가격·보조금·세율 로직**: DB에서 옴. 시안 금액은 예시
- **고객 서명 화면**: 전자서명 업체 화면. 우리가 설계하지 않음
- **스타일링 라이브러리 도입**: 하지 않음(혼재 금지)

---

## 5. 표기 관례

- 화면 금액은 **VAT 포함가**
- 숫자 `tabular-nums`, 천단위 콤마
- 날짜 `MM-DD`(당해) / `YY-MM-DD`(이전 연도)
- 문구는 사과가 아니라 다음 행동 안내 ("아직 없습니다" → "…해 보세요")

---

## 6. 각 단계 공통 체크리스트

배포 전 매번 확인:

1. 세 가지 화면 형태(넓은 데스크톱 / 태블릿 가로 / 세로로 긴 화면)
2. 긴 값(고객명 20·주소 40·상호 30·금액 9자리)에서 밀림 없음
3. hover 없이도 모든 정보·기능 접근 가능
4. 권한 조합별 요소 노출/숨김 정확
5. 스크롤 주체가 의도대로 (페이지 전체 스크롤 발생 안 함)
6. 되돌릴 수 없는 동작에 확인 단계
