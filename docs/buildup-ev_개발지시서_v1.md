# buildup-ev 개발 지시서 (Claude Code용) · v1

> Claude Code가 개발을 착수·진행할 때 따르는 **지시서**. 상세 데이터·수치·공식의 정답은 `docs/`(기획서·DB스키마·견적서 엑셀·하중계산기). 프로젝트 컨텍스트는 `CLAUDE.md`와 함께 읽을 것.
> ※ 본 지시서가 **최신 합의본**이다. 이전 문서와 충돌 시 여기 우선 (특히 "원가 기반 관리 제외", "권한별 기능 토글").

---

## 1. 제품 목적 (단계적)
- **단기**: 주문관리·영업의 디지털화·데이터화 / 1톤급 특장 설계·제작방안을 **EV& 방식으로 표준화**
- **중기**: EV& 설계 표준에 따른 **부품 공급망 확보**
- **장기**: 다양한 옵션·치수의 **다품종 소량생산 생태계** / **디지털 트윈 도면 → 특장 무인 자율생산** 기반

**포지셔닝**: 외부 판매 SaaS 아님 = **자사 판매 보조 도구**. 확장 경로 →
`1단계 내부 사용` → `2단계 EV& 영업사원 + 거점별 특장사` → `3단계 표준 설계로 부품 공급(현재 non-goal)`

---

## 2. 사용자 화면(3-Surface) & 권한
| 화면 | 사용자 | 핵심 + 조회 권한 |
|---|---|---|
| **영업** | EV& 영업·대리점 | 옵션선택→견적→주문 전환 · 보조금 자격(지역+소상공인→가용보조금) 표시 · 전체 진행 조회(제작·구변은 진행상황만) |
| **관리자** | EV& 내부 | 영업↔특장사 주문흐름 관제 · 상담기록·전체 세부 조회 · 보조금 DB 중앙관리 |
| **특장사** | 외주 특장사 | 픽스 견적·고객정보→행정서류·작업지시서 자동생성 · 구조변경 튜닝승인 신청까지 · 받은 차량·일정·서류만(영업기록 X) |

- **★ 관리자 페이지에 "계정·권한별 기능모듈 ON/OFF 토글"을 개발 초기부터 반영.** (RBAC + 모듈별 feature flag — 역할/계정 단위로 기능 노출 제어)
- 영업·특장사 사용자의 구체 정의와 관리자 포지션 일부는 `[미정 — 남주 정렬]`. 개발은 위 역할 기준으로 진행.

## 3. 견적 방식 (범위 명확화) ★중요
- **① 옵션 기반(기본)**: PV5 K1 — 옵션 선택 시 가격 변동(옵션값별 단가 합 → 공급가액 → 세금·보조금·등록비 → 실구매가). 회귀검증 케이스 = **₩46,471,818**(docs/견적서).
- **② 탑 자유설정(커스텀)**: 비표준 치수 시 **원자재를 길이별로 선정해 견적**. (탑 옵션 자유설정 유지)
- **원가 기반 "관리"는 범위에서 제외(삭제 완료).** 부품·원자재·공정·인건비·마진의 **원가 롤업/특장사 원가 컨트롤 시스템은 만들지 않는다.**
  - DB에서 **삭제됨**(스키마·템플릿 반영): `process`·`margin_rule` 테이블, `material.unit_price`·`part.unit_price`(단가), BOM 항목 중 공정.
  - **유지**: `material`(단위무게=하중계산용), `part`(무게만), `bom_line`(치수→소요량→무게, 무게=소요량×단위무게). ※ `material.unit_price`는 ② 탑 자유설정 견적 구현 시 재도입.

## 4. 개발 단계 & 일정
- **0단계**(단기 · 플래닝고 위임): PV5 차종 추가 · 3D 옵션 추가(격벽 등)·선택 개선 · **견적 로직 교체(원자재 원가 기반 → 옵션 기반)** · EV 양식 견적서 출력
- **1단계**(7~8월, "월 내 사용 가능" 목표): 영업 화면 — 0단계 3D뷰만 유지하고 **UI 전면 재설계** · 옵션 기반 견적 **내재화** · 고객별 견적 저장 (※ 관리자 페이지 일부 동시 개발 = 견적 데이터 적재)
- **2단계**(~9월 말 · **정부 과제 완료 조건**): 특장사+관리자 화면 · **부품·원자재 분리 정밀 하중계산(패널 면적→무게) → 재원표** · 행정서류 자동화
- **확장**(향후): 정밀 하중계산 고도화 · 차량번호·제원 자동조회 · 보조금 자동조회(일부 불가/유료)

---

## 5. 시스템 구성 / 데이터 흐름
- **플래닝고 = 3D 코어만**: 차량 3D 렌더, 옵션값(VIVAR 경유) 기반 3D 즉시 생성, **치수 산출**, 외관 사면도(정면·측면·후면) 추출.
- **EV& = 나머지 전부**: 옵션 화면 · 견적 · 하중계산·법규 · 서류 자동생성 · 주문/업무흐름 · 문서보관함 · 인증·권한 · 기준데이터 관리.
- **원칙**: VIVAR는 치수·도면만 제공, 무게·하중·견적·서류 계산은 전부 EV&.
- **VIVAR 수신 치수**: 전장·전폭·전고(외측, 특장 반영) + 하대 외측/내측 L·W·H + 하대옵셋트. (축간거리·윤간거리는 차종마스터 고정 / 상승높이·다축은 범위 밖)

## 8. 개발 순서 (Task 흐름)
1. **DB**: schema(SQL) + 채워진 데이터 → seed(CSV)
2. **백엔드 — 옵션·견적 API**(옵션 기반): 회귀검증 ₩46,471,818
3. **프론트 — 영업 화면**(3D iframe + 옵션 패널 + 견적 + 고객별 저장)
4. **관리자 — 권한별 기능 토글 + 견적 데이터 적재**(1단계 일부 동시)
5. **백엔드 — 하중계산**(치수·무게 → 분포·부하율·적합판정): PV5로 하중계산기 결과와 일치 검증
6. **특장사 화면 + 서류 자동생성**(제원대비표·외관도·작업지시서) + 튜닝승인 신청 지원
7. (커스텀) **탑 자유설정 견적**(원자재 길이별)
