# 0단계 · 폰트 고정 (최우선, 단독 배포)

```
⚠️ 배포·안전 규칙 (CLAUDE.md 준수)

UI 개편 0단계: 웹폰트를 Pretendard로 고정한다. 이것만 하고 배포한다.

반드시 먼저 읽을 것:
- docs/ui-revamp-plan.md  (0단계 항목)
- docs/design-system.md   (§0 macOS 톤, §2 타이포그래피)

## 왜 이걸 먼저 하는가
지금 시스템 폰트만 쓰고 있어 macOS는 Apple SD Gothic Neo, Windows는 맑은 고딕,
Android는 Noto Sans KR로 떨어진다. 한글은 폰트별 글자 폭 차이가 커서 표 헤더가 두 줄로
접히고 버튼 라벨이 줄바꿈된다. 폰트가 바뀌면 모든 글자 폭이 달라지므로 반드시 먼저 고정한다.

## 작업
1. Pretendard **자체 호스팅** (CDN 의존 금지 — 현장 네트워크·차단 리스크)
   - frontend/public/fonts/ 에 woff2 배치
   - subset: 한글 + 라틴 + 숫자
   - weight는 400 / 500 / 600 **세 개만** (용량 절감)
   - font-display: swap
2. globals.css 에 @font-face 정의 + 전역 적용
   font-family: Pretendard, -apple-system, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif;
3. 전역 규칙 추가
   - word-break: keep-all   (한글 단어 중간 끊김 방지)
   - font-variant-numeric: tabular-nums  (금액·수량 자릿수 정렬)
4. 라이선스 파일 동봉 (Pretendard = SIL OFL)

## 검증 (전부 통과해야 완료)
1. 전 화면에서 표 헤더가 2줄로 접히지 않는다
2. 버튼 라벨이 줄바꿈되지 않는다
3. 아래 긴 값에서 레이아웃이 밀리지 않는다
   고객명 20자 · 주소 40자 · 상호 30자 · 금액 9자리(억 단위)
   → 더미 데이터에 이 최대 길이를 넣어 확인할 것
4. 폰트 로딩 실패 시 폴백(맑은고딕 등)에서도 화면이 깨지지 않는다
5. 네트워크 탭에서 woff2가 자체 도메인에서 로드된다 (외부 CDN 요청 없음)
6. 기존 테스트 전부 통과, 콘솔 에러 0

## 하지 말 것
- 색·간격·컴포넌트는 이번에 건드리지 않는다. 폰트만.
- 폰트 크기 체계 변경도 1단계에서 한다.

## 순서
문서 정독 → 폰트 파일 준비 → @font-face → 전역 적용 → 긴 값 더미로 검증 →
스크린샷으로 전후 비교 보고 → 커밋 목록 보여주고 멈춤(push 금지)

UI 개편 1단계: 디자인 토큰과 공통 컴포넌트만 교체한다. 화면 로직은 건드리지 않는다.

- docs/design-system.md    (전체 — 이 문서가 스펙)

## 작업 1 — globals.css 토큰 정의
design-system.md 의 값을 CSS 변수로 정의:
- 색: --lime --dark --body --muted --line --card --bg --warn --warnbg
      + 파생 --lime-bg --shadow-1 --shadow-2 --track
- 타이포 5단계: --fs-title(20/600/-.01em) --fs-section(15/600/-.01em)
      --fs-body(14/400) --fs-label(13/500) --fs-caption(12/400)
- 간격 6단계: --sp-1(4) ~ --sp-6(32)
- 반경 3단계: --r-sm(6) --r-md(10) --r-pill(999)
★ 컴포넌트에 숫자를 직접 쓰지 않는다. 변수만 참조.

## 작업 2 — 공통 컴포넌트 (macOS 톤)
design-system.md §0 의 5가지를 반드시 지킬 것:
  테두리 0.5px 헤어라인 / 그림자 0 1px 2px rgba(0,0,0,.04) /
  제목 letter-spacing -0.01em / 모서리 10px(카드) 6px(컨트롤) / 탭 = 세그먼티드

- **헤더**: EV& 로고 + 세로 구분선 + 워드마크 "Buildup-EV"
  워드마크는 굵기 700, letter-spacing -0.035em (로고는 800/-0.05em 이라 반 단계 위계)
- **세그먼티드 탭**: 역할 전환(영업·관리·특장). 트랙 --track, 선택 시 흰 알약 + --shadow-1
- **화면 탭**: 밑줄 방식 (역할 탭보다 약하게 — 계층 위계)
- **버튼 4종**: Primary(--dark) / Secondary(흰+헤어라인) / Danger(--warn 테두리) / Disabled
  높이 36px, 터치 시 44px
- **눌림 모션**: transform: scale(.97) + 비대칭 트랜지션
  누를 때 90ms ease / 뗄 때 260ms cubic-bezier(.34,1.4,.64,1) 스프링
- **입력·뱃지·빈 상태**: design-system.md §11 §12
- **동심원 반경**: 중첩 요소는 (바깥 반경 − 여백)으로 안쪽 반경 축소

## 작업 3 — 파비콘 연결 확인
frontend/public/ 에 icon-*.svg, favicon.ico, icon-*.png, site.webmanifest 이미 있다.
index.html 에 연결되어 있는지 확인만 (이미 되어 있으면 건드리지 말 것).

## 반드시 지킬 원칙
- **hover 금지 규칙**: 정보·기능을 hover에 숨기지 않는다. hover는 테두리 톤 변화 정도만.
  (태블릿에서는 hover를 영영 볼 수 없다)
- **저대비 금지**: 라임 배경 위 흰 글씨 금지. 라임 위 텍스트는 --dark.
- 금액·날짜는 white-space: nowrap + tabular-nums

## 검증
1. 모든 화면에서 헤더·버튼·탭이 동일하게 보인다
2. 버튼 눌림 반응이 세 화면 형태 모두에서 동작
3. hover 없이도 모든 기능 접근 가능
4. 긴 값(고객명 20·주소 40·금액 9자리)에서 밀림 없음
5. 기능 회귀 없음, 기존 테스트 통과, 콘솔 에러 0

## 순서
design-system.md 정독 → 토큰 → 공통 컴포넌트 → 전 화면 육안 확인 →
커밋 목록 보여주고 멈춤(push 금지)

## 앱 대비 제약 (docs/app-plan.md §1)
- **계산 로직은 shared/ 에만 둔다.** 컴포넌트에서 금액·보조금·세율을 다시 계산하지 말 것.
  화면은 결과를 표시만 한다. 가격바에 계산식이 들어가 있으면 shared/ 로 옮길 것.
- **저장되는 최종 금액은 서버 계산값** 기준. 화면 표시값은 참고.
- 정책·안내 문구를 코드에 하드코딩하지 말 것.

## 절대 조건
1. **3D는 항상 16:9.** 컨테이너 쿼리로 계산하는 현재 방식을 유지한다.
   CSS aspect-ratio 단독 사용 금지(실제로 비율이 깨진다). 3D 자리에 무엇이 들어가든
   (로딩·에러·플레이스홀더) 16:9를 지킨다. 나머지 레이아웃이 3D에 맞춘다.
2. **VIVAR iframe 내부는 건드리지 않는다.** 시각화 전용이다.
3. **스크롤 주체 = 우측 옵션 패널.** 페이지 전체 스크롤이 생기면 안 된다.
   헤더 · 3D · 하단 가격바는 고정.
4. **고객 노출 원칙**: 이 화면에 다른 고객의 이름·연락처·금액이 어떤 형태로도
   나타나지 않아야 한다. 상담 중 고객이 함께 보는 화면이다.

## 작업
- 옵션 카드: 선택 시 --lime 2px + --lime-bg (패딩 -1px 보정), 누름 scale(.97)
- **트림 사양은 hover 펼침이 아니라 명시적 토글 버튼**으로 (태블릿 대응)
- 하단 가격바: 수식 흐름(차량+특장 − 혜택 − 보조금 = 실구매가) 유지,
  금액 nowrap + tabular-nums
- 견적 저장 버튼 = quote.create 권한. 권한 없으면 **숨김**(비활성 아님)
- 화면 금액은 VAT 포함가 표기

## 검증
1. 세 가지 화면 형태에서 3D가 16:9 유지
   ① 넓은 데스크톱 ② 태블릿 가로 ③ 세로로 긴 화면
2. 페이지 전체 스크롤 없음 (우측 패널만 스크롤)
3. hover 없이 모든 옵션·사양 접근 가능
4. 긴 값에서 가격바·옵션명 밀림 없음
5. 라임 위 흰 글씨 없음(저대비 금지)
6. quote.create 없는 계정에서 저장 버튼이 보이지 않음
7. 기능 회귀 없음, 콘솔 에러 0

## 순서
문서 정독 → 스크롤 구조 → 옵션 카드 → 가격바 → 권한 → 세 화면비 검증 →
커밋 목록 보여주고 멈춤(push 금지)

- 진행 중 재클릭 무시(중복 요청 차단)

## 검증
1. 긴 값 리스트에서 밀림 없음 (고객명 20 · 주소 40 · 상호 30 · 금액 9자리)
   → 더미 데이터에 최대 길이 포함
2. 권한 조합별로 버튼이 정확히 나타나고 사라진다
3. 되돌릴 수 없는 동작에 확인 단계가 있다
4. PDF 생성 실패를 인위적으로 만들어 재시도가 동작하는지 확인
5. 페이지 전체 스크롤 없음
6. 기능 회귀 없음, 콘솔 에러 0

===================================================

UI 개편 4단계: 관리자 화면(견적목록·영업성과·주문칸반·기능모듈·계정관리·무게상수·옵션DB).

반드시 먼저 읽을 것: docs/ui-revamp-plan.md (4단계, §2 권한), docs/design-system.md,
docs/app-plan.md (§1)

## 앱 대비 제약 (docs/app-plan.md §1)
- **계산 로직은 shared/ 에만.** 옵션DB·무게상수 화면에서 값을 재계산하지 말 것.
- 기준값(단가·보조금·세율)은 **DB에서 오는 것**이지 코드 상수가 아니다. 하드코딩 금지.

## 작업
1. **탭 구조 정리** — 7개가 평평하게 나열되어 위계가 없다. 성격별 그룹핑을 제안하고
   나에게 확인받은 뒤 적용할 것:
     운영: 견적목록 · 영업성과 · 주문칸반
     기준정보: 옵션DB · 무게상수 · 계정관리 · 기능모듈
2. **표 정렬 ★** — 지금 줄이 어긋난다. 반드시:
   - 헤더와 본문이 같은 grid-template-columns 값을 공유
   - 숫자 열은 고정폭 + 우측정렬 + tabular-nums
   - 이름 열만 1fr 로 늘어나고 넘치면 말줄임(부모 min-width:0)
   - 헤더 행 고정, **표 본문만 스크롤**
3. **좁은 폭 대응**: 가로 스크롤. **컬럼을 숨기지 말 것** — 데이터 누락으로 오해된다
4. **옵션DB**: 변경 이력 / 되돌리기는 Danger 스타일 + 확인 단계
5. **칸반**: 컬럼 내부 스크롤. 드래그는 order.control 권한

## 권한
  영업성과(전체) stats.all / 옵션DB·무게상수 basedata.manage /
  계정관리·기능모듈 account.manage / 칸반 이동 order.control
- 권한 없으면 **탭 자체를 렌더하지 않는다**(빈 탭 금지)
- 탭이 전부 숨겨지는 경우의 화면도 정의할 것

## 검증
1. 표 세로줄 어긋남 0 — 값 길이가 달라도 흔들리지 않음
2. 좁은 폭에서 가로 스크롤, 컬럼 숨김 없음
3. 권한 조합별 탭 노출/숨김 정확, 탭 0개인 경우 화면 정상
4. 페이지 전체 스크롤 없음(표 본문·칸반 컬럼만 스크롤)
5. 기능 회귀 없음, 콘솔 에러 0

```
⚠️ 배포·안전 규칙 — 위와 동일

===================================================

UI 개편 6단계: 태블릿 대응. 구조는 이미 심어져 있고 적용·검증 단계다.

반드시 먼저 읽을 것: docs/ui-revamp-plan.md (6단계, §1-3 §1-5 §1-6), docs/design-system.md §4

## 절대 조건 — 분기 기준이 화면 폭이 아니다
폭으로 태블릿을 판단하면 데스크톱으로 오인한다. 반드시:
  세로형 판정: (height/width) > 1 → 가격 블록 가로 → 세로 배치
  터치 판정:   @media (pointer: coarse) → 여백 축소, 히트영역 확대

## 작업
1. 터치 히트영역 **44×44px** — 표 내부 버튼도 예외 없음
   (지금 표 안 버튼은 폰트 11로 작아서 손가락 오탭이 난다)
2. 되돌릴 수 없는 동작에 확인 단계 필수 적용
3. **화면 회전 시 상태 유지** — 상담 중 세로↔가로가 바뀐다.
   진행 중이던 입력·선택 옵션이 보존되어야 한다
4. **소프트 키보드 대응** — 화면 절반을 먹는다. 고객정보 입력은 필드가 많은데
   페이지 전체 스크롤이 없어 입력칸이 가려지기 쉽다.
   → 모달 내부 스크롤 + 포커스된 필드가 보이도록 스크롤
5. **"상담 모드" 검토** — 내부 정보(다른 고객 목록·실적) 숨김 토글.
   설계안을 먼저 제안하고 나에게 확인받을 것

## 검증 (실기기 필수)

4. 표 내부 버튼 오탭 없음
5. hover 없이 모든 기능 접근 가능
6. 야외 밝기에서 대비 확인(라임 위 흰 글씨 없음)
