# 개발 프롬프트 — 옵션 선택 → 자동 하중·법규·서류 (PV5 실측 BOM 연동)

> Claude Code에게 주는 통합 지시. 실측 데이터(`option-weights-real.json`, 정정된 `pv5-spec.json`/`vehicle_model.csv`) 기준으로 "옵션 한 번 선택 → 하중계산·법규검토·구조변경 서류 자동생성"을 완성한다.
> 데이터 소스: `260701 STEGO K1 Spec` 중량 계산시트(최종설계). **'인증용' 계산값·'용량비교' 시트는 사용하지 않는다.**

---

## 적용 범위
- **PV5 오픈베드 기준만** 진행. 베이스 공차 1905(데크 포함), 탑 설치 = 오픈베드 데크 탈거 + 탑 설치.
- **샤시캡은 추후 추가 예정** — 데크가 없어 탈거 항목이 다름. 별도 model_code(`PV5_CABCHASSIS` 등)로 확장하되 지금은 범위 밖.

## 0. 확정 사양 (이미 검증됨)
- **좌표계**: `CG_x = 전축(front axle) 기준 거리`. load-calc 입력값 `dist_to_rear_axle_mm = 축간거리(2995) − CG_x`.
- **하중 계산식**: `후축반력 = W × CG_x / 축간거리`, `전축반력 = W − 후축반력` (shared/load-calc과 동일 — 검증됨: 적차 전축 1285·후축 1395 = 제원표 일치).
- **법규 판정**: ① 적차 총중량 ≤ **2680**(제작허용총중량 상한, 사용자 결정. gvw_limit_kg=2680) ② 타이어 부하율 = 축하중 / (타이어허용 750 × 2) ≤ 100%.
- **배치**: 하중·법규·서류는 **영업 화면 아님**. **관리자 페이지 + 특장사 페이지의 주문 상세(사양 조회)** 에만 노출. 마스터=전체 열람, 특장사=자기 범위.

## 1. DB 정정 반영 (seed 재실행)
`doc-templates/pv5-spec.json`, `db/seed/vehicle_model.csv` 이미 정정됨:
- 윤간거리 1551/1453 → **1617/1625**
- 원동기 **DD4S 120kW/4600~9000rpm**, 구동축전지 **402V / 177Ah**, CATL 각형 NCM, REESS-SWL(EV)
- 전비 복합4.1/시가4.7/고속3.6, 주행거리 330/370/282
- 차체형상 세미본네트형, 형식코드 SW1-O-21L6-A-G7A, 차대번호 KNCWAX71, 모델연도 2026
- 축별설계허용하중 전1400/후1560, 제작허용총중량 2680
→ **작업**: seed upsert 재실행해 vehicle_model 반영. `pv5-spec.json`은 서류 생성 시 로드.
- `gvw_limit_kg` = **2680** 확정(사용자 결정). vehicle_model.csv 반영됨. (차량총중량 2635는 적차 실제무게로 유지.)

## 2. 옵션 → BOM 키 매핑 (도어구성 옵션은 이미 존재)
중량시트상 **도어구성이 무게·최대적재량을 바꾼다.** 옵션 그룹 신설 불필요 — 기존 `DOORTYPE × DOORADD`를 BOM 도어구성 키로 매핑한다.
- `DOORADD`(추가없음→기본 2도어 / 운전석측추가→4도어) × `DOORTYPE`(여닫이 / 슬라이딩):
  - 여닫이 + 추가없음 → `기본_여닫이`
  - 슬라이딩 + 추가없음 → `기본_슬라이딩`
  - 여닫이 + 운전석측추가 → `4도어_여닫이`
  - 슬라이딩 + 운전석측추가 → `4도어_슬라이딩`
- `BODYTYPE`: BODY_REEFER→냉동탑, BODY_DRY→내장탑. `TOP`: TOP_LOW→저상, TOP_STD→표준.
- 조합 키 = `BODYTYPE × TOP × (DOORTYPE×DOORADD)` → `option-weights-real.json` `탑_설치`에서 완성무게·최대적재량 조회.
- 냉동탑은 냉동기 포함(별도 옵션 아님).
- **양문미닫이(DOOR_FOLD)**: 옵션 시드에 추가 완료. **내장탑(BODY_DRY) 선택 시에만 노출/선택 가능, 냉동탑 선택 시 비활성**(UI 제약). BOM 키 `양문미닫이`로 매핑.

## 3. 옵션 → 탈거/설치 항목 자동 생성 (실측 BOM 연동)
`option-weights-real.json` 사용:
- **탈거**: `기본_탈거` = 오픈베드 데크 (무게 252 ※역산 — 실측 확인필요, CG_x 3050).
- **설치**: `탑_설치[유형][크기][도어구성]` 완성무게 1개 항목 (CG_x 3050) + 선택된 `개별_옵션_항목` 중 `무게계산_포함:true`인 것(데칼·썬팅·블랙박스·지급품).
- **무게계산 제외(사용자 결정)**: 온도기록계·격벽·스포일러는 `무게계산_포함:false` → 하중계산 합산에서 제외(서류엔 선택 옵션으로만 표기).
- **차량중량_후** = 1905 − Σ탈거 + Σ설치.
- **최대적재량_후** = 선택 조합의 `최대적재량_kg`.
- 항목은 **가변 행**: 서류/하중계산서에 항목 수만큼 행 생성.

## 4. 자동 하중계산 (shared/load-calc)
입력 구성 (모두 후축까지거리로 변환해 전달):
- `remove_items`: 탈거 항목 [{weight, dist_to_rear_axle = 2995 − CG_x}]
- `install_items`: 설치 항목 동일 변환
- `crew_items`: 정원 130kg @ CG_x 1100 → 후축까지 1895
- `cargo`: 최대적재량_후 @ CG_x 2400 → 후축까지 595
- `curb_axle_front/rear`: 1105 / 800, `wheelbase`: 2995, `tire`: 750
출력: 공차/적차 전·후축 하중(전/후 비교), 타이어 부하율, 앞바퀴 분포율.

## 5. 법규검토
- 총중량: 적차 총중량 ≤ 2680 → OK/NG 배지
- 축하중: max(전축, 후축) 부하율 ≤ 100% (타이어허용 750×2 기준)
- 종합 판정. (치수 기준 최대허용제원은 VIVAR 치수 연동 후 — 지금은 하중 기준만.)

## 6. 서류 자동생성 (HTML→puppeteer PDF, 견적서와 동일 파이프라인)
`doc-templates/*.html` 바인딩:
- `주요제원대비표.html`: 별지 제33호의2서식 충실재현. 전값=pv5-spec/vehicle_model, 후값=옵션 산출(차량중량·최대적재·하대치수·하중분포·하대옵셋트). 예시 PDF와 렌더 스크린샷 시각대조로 셀구조 정밀화.
- `하중계산서.html`: 예시 PDF 시각대조 재현. **탈거/설치 가변행**(`{{#탈거항목}}`/`{{#설치항목}}`), 하중분포·부하율·법규판정.
- `작업지시서.html`: EV& 양식, `{{#옵션목록}}` 반복.
- 한글 폰트(Pretendard/Noto Sans KR) 임베드 후 PDF.

## 7. 게이트·업로드 (기존 유지)
- 튜닝신청 게이트: 필수서류(제원대비표·하중계산서·작업지시서 자동생성분) 완비 시 진행. 예비변경허가서=선택. 자동차등록증·튜닝승인서=업로드.
- 특장사 '차량정보 입력' 폼(등록증 기반): 제원관리번호·등록번호·차대번호·형식코드·모델연도 → 서류 ④출처 바인딩.

## 8. 검증 (필수)
- 크롬으로 관리자/특장사 주문 상세 진입 → 옵션 조합 바꿔가며 하중·법규·서류 값이 **옵션에 따라 자동 갱신**되는지 확인.
- 냉동탑 저상 기본 조합 → 하중계산 결과가 제원표(공차 후축 950·적차 1285/1395)와 **근사**한지 스크린샷 대조. (오픈베드 데크 역산 252 때문에 오차 가능 → 로그로 확인.)
- 콘솔 에러 0, 견적서 PDF 200 유지.

## 확정 사항 (반영 완료)
- 법규 총중량 상한(gvw_limit) = 2680 ✔ (차량총중량 2635는 실제 적차무게로 유지)
- 양문미닫이 = 내장탑 전용, DOOR_FOLD 시드 추가 ✔
- 온도기록계·격벽·스포일러 = 무게계산 제외 ✔
- 범위 = 오픈베드만, 샤시캡 추후 ✔
