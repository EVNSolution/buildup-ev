# [Claude Code용] 옵션 선택 → 자동 하중·법규·서류 개발 프롬프트

> 아래 블록 전체를 복사해 Claude Code에 붙여넣으세요.

---

buildup-ev 리포에서 **"옵션 한 번 선택 → 하중계산·법규검토·구조변경 서류가 자동 생성/갱신"** 되는 기능을 완성해줘. 대상은 **PV5 오픈베드**. 아래 데이터·규칙은 이미 확정·검증됐으니 그대로 따르고, 임의 추정으로 값을 바꾸지 마.

## 먼저 읽을 파일
- `buildup-ev/doc-templates/option-weights-real.json` — 실측 BOM(탑 완성무게·최대적재량·탈거/설치·CG). **이 파일이 무게/위치의 단일 소스.**
- `buildup-ev/doc-templates/pv5-spec.json` — PV5 오픈베드 차종 고정 제원(서류용, 실측 정정본).
- `buildup-ev/doc-templates/{주요제원대비표,하중계산서,작업지시서}.html` — 서류 HTML 템플릿.
- `shared/load-calc/*` — 하중계산 코어.
- `buildup-ev/db/seed/{vehicle_model,option_group,option_value,tire}.csv` — 시드.

## 확정 규칙 (변경 금지)
1. **좌표계**: `CG_x = 전축(front axle) 기준 거리`. load-calc 입력 `dist_to_rear_axle_mm = 2995 − CG_x`.
2. **계산식**: `후축반력 = W × CG_x / 2995`, `전축반력 = W − 후축반력`. (검증: 냉동탑 저상 적차 전축 1285·후축 1395 = 제원표 일치.)
3. **법규**: ① 적차 총중량 ≤ **2680**(gvw_limit) ② 타이어 부하율 = 축하중 ÷ (750 × 2) ≤ 100%.
4. **노출 위치**: 하중·법규·서류는 **영업 화면 금지**. **관리자 + 특장사 주문 상세(사양 조회)** 에만. 마스터=전체, 특장사=자기 범위.
5. **범위**: 오픈베드만. 샤시캡은 추후 별도 model_code.

## 작업 순서

### 1) 옵션 → BOM 매핑
- 조합 키 = `BODYTYPE(BODY_REEFER=냉동/BODY_DRY=내장) × TOP(TOP_LOW=저상/TOP_STD=표준) × 도어구성`.
- 도어구성 = 기존 `DOORTYPE × DOORADD` 매핑:
  - 여닫이+추가없음→`기본_여닫이`, 슬라이딩+추가없음→`기본_슬라이딩`, 여닫이+운전석측추가→`4도어_여닫이`, 슬라이딩+운전석측추가→`4도어_슬라이딩`
  - **양문미닫이(DOOR_FOLD)**→`양문미닫이`: **내장탑 전용**. 냉동탑 선택 시 UI에서 DOOR_FOLD 비활성. (시드에 DOOR_FOLD 추가돼 있음 — seed 재실행 필요.)
- 선택 조합으로 `option-weights-real.json.탑_설치`에서 **완성무게·최대적재량** 조회.

### 2) 탈거/설치 항목 자동 생성 (가변 행)
- 탈거: `기본_탈거`(오픈베드 데크, 252kg, CG_x 3050).
- 설치: 탑 완성무게 1항목(CG_x 3050) + `개별_옵션_항목` 중 `무게계산_포함:true`(데칼·썬팅·블랙박스·지급품)만.
  - 온도기록계·격벽·스포일러는 `무게계산_포함:false` → **하중계산 제외**, 서류엔 선택 옵션으로만 표기.
- 차량중량_후 = 1905 − Σ탈거 + Σ설치. 최대적재량_후 = 선택 조합값.

### 3) 자동 하중계산 (shared/load-calc)
입력(모두 후축까지거리로 변환): remove_items/install_items = 위 항목, crew_items = 정원 130kg @CG_x 1100, cargo = 최대적재량_후 @CG_x 2400, curb_axle 1105/800, wheelbase 2995, tire 750.
출력: 공차/적차 전·후축 하중, 타이어 부하율, 앞바퀴 분포율. **옵션 바뀌면 즉시 재계산.**

### 4) 법규검토
총중량 ≤ 2680(gvw_limit), 부하율 ≤ 100% → 각 OK/NG 배지 + 종합판정. (치수 기준은 VIVAR 연동 후 — 지금 제외.)

### 5) 서류 자동생성 (HTML→puppeteer PDF, 견적서와 동일 파이프라인)
- `주요제원대비표.html`: 별지 제33호의2서식 충실재현. 전값=pv5-spec/vehicle_model, 후값=옵션 산출. 예시 PDF(`99. 구조변경 서류 예시/4813/[최종] 주요제원 대비표.pdf`)와 렌더 스크린샷 시각대조로 셀구조 정밀화.
- `하중계산서.html`: 예시 PDF 시각대조 재현. 탈거/설치 가변행(`{{#탈거항목}}`/`{{#설치항목}}`) + 하중분포·부하율·법규판정.
- `작업지시서.html`: `{{#옵션목록}}` 반복.
- 한글 폰트(Pretendard/Noto Sans KR) 임베드 후 PDF.

### 6) 게이트·업로드 (기존 유지)
튜닝신청 게이트: 자동생성 필수서류 완비 시 진행. 예비변경허가서=선택. 자동차등록증·튜닝승인서=업로드. 특장사 '차량정보 입력' 폼(제원관리번호·등록번호·차대번호·형식코드·모델연도)을 서류에 바인딩.

### 7) DB 반영
seed upsert 재실행 → vehicle_model(윤간 1617/1625) + option_value(DOOR_FOLD) 반영.

## 검증 (필수, 끝나고 크롬으로 직접)
- 관리자/특장사 주문 상세에서 옵션 조합을 바꿔가며 하중·법규·서류가 **옵션대로 자동 갱신**되는지 확인.
- 냉동탑 저상 기본 조합 결과가 제원표(공차 후축 950, 적차 1285/1395)와 근사한지 스크린샷 대조(데크 역산 252 오차 감안).
- 콘솔 에러 0, 견적서 PDF 200 유지.
