# 구조변경 서류 HTML 양식 (서류 자동생성용)

> Claude Code가 서류 PDF를 생성할 때 **이 폴더의 HTML 템플릿을 기준**으로 한다(견적서 PDF와 동일하게 HTML→puppeteer PDF). `{{placeholder}}`에 데이터를 바인딩.
> 양식이 미확정/변경되면 **이 HTML만 수정**하면 됨(데이터 바인딩은 그대로).

## 파일
| 파일 | 서류 | 양식 출처 |
|---|---|---|
| `주요제원대비표.html` | 튜닝 전·후 주요제원 대비표 | 자동차관리법 시행규칙 별지 제33호의2서식(충실 재현). 예시: `99. 구조변경 서류 예시/4813/[최종] 주요제원 대비표.pdf` |
| `하중계산서.html` | 하중 계산서 | TS 하중계산 형식 + EV& 브랜드. 예시: `…/[최종] 4813 하중계산.pdf` |
| `작업지시서.html` | 작업 지시서 | EV& 자체 양식(공식 양식 없음) |
| `pv5-spec.json` | PV5 차종 고정 제원 데이터 | kia.com 등 인터넷 확인 + 차종마스터 DB |
| `option-weights-real.json` | ★★옵션 → 탈거/설치 항목(무게·위치) 실측 BOM | STEGO K1 Spec 중량 계산시트(최종설계) 기준. 탑종류×크기×도어구성 완성무게·최대적재량. **이 파일을 사용.** |
| `option-weights-demo.json` | (구) 시연 가정값 | option-weights-real.json으로 대체됨 — 미사용 |
| `개발프롬프트_옵션→자동서류.md` | ★옵션→자동 하중·법규·서류 통합 개발 지시 | Claude Code 작업 지시서 |

※ **외관도·세부도면**: 도면(이미지/CAD)이라 폼 템플릿 아님 → VIVAR 치수/도면라이브러리 연동 후. 데모는 placeholder.
※ **예비변경허가서**: 지자체 발급 → 양식 안 만듦. 튜닝신청 게이트에서 **선택(optional)** 처리.
※ **자동차등록증·튜닝승인서**: 업로드 문서(생성 X).

## 데이터 출처 매핑 (각 placeholder를 어디서 채우나)
`{{ }}`를 채울 출처 분류:

**① 차종 자동 — `pv5-spec.json` + 차종마스터 DB(vehicle_model)**
차명·종별·구분·차체형상·구동방식·사용연료·승차정원·유형(전)·차체제원(전)·축간거리·윤간거리·공차중량(전)·최대적재량(전)·차량총중량·제작허용총중량·타이어형식·원동기(전동기 출력/토크/배터리)·주행거리·변속기

**② 하중계산 결과 — `shared/load-calc`**
공차/적차 시 하중분포(전·후축, 튜닝 전/후)·타이어 하중율·앞바퀴 분포율·하대옵셋트(전/후)·총중량

**③ 영업 입력 — 고객정보(quote.customer)**
소유자 주소·소유자 성명(법인명)·용도

**④ 특장사 입력 — 차량 인계 후(자동차등록증). 주문 상세 '차량정보 입력' 폼**
제원관리번호·등록번호·최초등록일·차대번호(1~8)·형식코드·모델연도
→ 데모에선 더미값 입력.

**⑤ 튜닝 후 결과 — 옵션/특장 작업(일부 VIVAR 치수 연동 후)**
차량중량(후)·최대적재량(후)·차체제원(후)·하대내측지수(후)·하대옵셋트(후)·유형(후)·용도(후)·튜닝개요(옵션→문장 자동 가능)·비고
→ 데모: 특장 입력 또는 더미.

**⑥ 더미(정밀값 미확인)**
형식코드·구동축전지 정격전압/용량 정확값·전비 복합/시가지/고속 정확값
→ 근사값 또는 `-`.

## Claude Code 작업 지시
1. 위 ①~⑥ 출처대로 데이터를 모아 각 템플릿의 `{{placeholder}}`에 바인딩 → puppeteer로 PDF 생성(견적서 PDF와 동일 파이프라인).
2. ★`주요제원대비표.html` = **자동차관리법 시행규칙 별지 제33호의2서식**. 반드시 **공식 서식과 동일한 셀 구조로 재현**할 것.
   - 기준(정답) = 예시 PDF `99. 구조변경 서류 예시/4813/[최종] 주요제원 대비표.pdf` (이게 채워진 별지 제33호의2서식).
   - 방법: 예시 PDF를 열어두고 → HTML 렌더 → **스크린샷으로 시각 대조** → 셀(rowspan/colspan)·항목 배치를 **PDF와 일치할 때까지 반복 조정.** (오른쪽 26 원동기 블록: 사용연료/내연기관/구동전동기/구동축전지/연료전지/하이브리드, 27 연료소비율, 28 윤간거리, 29 변속기, 30 타이어형식, 31 구동방식, 32 차대번호가 왼쪽 12~25행과 높이 맞춰 들어감.)
   - 현재 HTML은 항목·데이터 바인딩 골격일 뿐 — 레이아웃은 위 대조로 정확히 완성.
   - 더 확실히 하려면: 법제처 등에서 별지 제33호의2서식 공식 한글/PDF 양식을 구해 그 위에 데이터만 채우는 방식도 가능.
3. ★`하중계산서.html` = 예시 PDF `99. 구조변경 서류 예시/4813/[최종] 4813 하중계산.pdf`를 **시각 대조해 정밀 재현**(제원대비표와 동일 방식 — 렌더→스크린샷→비교→조정 반복). 양식 글자가 이미지라 텍스트 추출이 안 되니 반드시 시각 대조.
   - ★탈거/설치 항목은 옵션 사양에 따라 **가변 행**(`{{#탈거항목}}`/`{{#설치항목}}`, 각 명칭·중량·위치). 예: 냉동기+냉동탑=설치 2행, 내장탑만=설치 1행.
   - 하중계산은 탈거/설치 **항목들을 합산(중량·모멘트)**해 전/후축 하중·부하율 산출.
4. `작업지시서.html`의 `{{#옵션목록}}…{{/옵션목록}}`은 주문 옵션 반복.
4. 한글 폰트 임베드(Pretendard 또는 Noto Sans KR), 폰트 로드 후 PDF.
5. PV5 외 차종 추가 시 `pv5-spec.json`과 같은 형식으로 차종별 spec 추가.
